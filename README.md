# Coolify Jev Failures

Install the live TLS dependency / Installez la dépendance TLS pour l'usage réel / Instale la dependencia TLS para uso real: `python3 -m pip install -r requirements.txt`.

## English

Review failed Coolify deployments with a finite, versioned Jev decision: `image`, `permissions`, `configuration`, `startup`, `network`, or `review`. The webhook stores a deployment UUID in SQLite and returns quickly; a separate worker fetches the deployment's logs using the [Coolify deployment API](https://coolify.io/docs/api/endpoints/deployments/get-deployment-by-uuid), selects the first explicit error line, redacts common secret patterns, and classifies it. No restart, rollback, or deployment is triggered. The result store contains identifiers and decisions, never full logs. Uncertain decisions go to `review`.

Offline: `python3 app.py --demo` and `python3 -m unittest discover -s tests -v`. For a live setup, set `COOLIFY_WEBHOOK_SECRET` (a random string of at least 16 characters), `COOLIFY_ORIGIN`, `COOLIFY_API_TOKEN`, and `TYPESAFE_API_KEY` privately. Run `python3 app.py --serve` and `python3 app.py --worker` as separate processes, then inspect decisions with `python3 app.py --results`. Configure Coolify's notification webhook URL as `https://YOUR-AUTHENTICATED-INGRESS/webhook/YOUR-SECRET`. The service binds to loopback; put an HTTPS ingress in front of it. Protect the URL from access logs because it contains a secret. Coolify does not sign these webhooks and its documented delivery behavior does not retry merely because of a non-2xx response, so persistent local queueing happens before processing. A crash after a remote Jev response but before committing SQLite can repeat the Jev call. Redaction is best effort; avoid sending sensitive deployment logs without an appropriate data policy. The Jev API was exercised with synthetic input; no live Coolify instance was available.

## Français

Examinez les déploiements Coolify échoués avec une décision Jev bornée et versionnée : `image`, `permissions`, `configuration`, `startup`, `network` ou `review`. Le webhook enregistre l'identifiant du déploiement dans SQLite et répond rapidement ; un processus séparé récupère les logs par l'[API Coolify](https://coolify.io/docs/api/endpoints/deployments/get-deployment-by-uuid), sélectionne la première ligne d'erreur explicite, masque les formes courantes de secrets et la classe. Aucun redémarrage, retour arrière ou déploiement n'est déclenché. La base conserve les identifiants et décisions, jamais les logs complets. Les décisions incertaines vont à `review`.

Hors ligne : `python3 app.py --demo` et `python3 -m unittest discover -s tests -v`. Pour un usage réel, définissez en privé `COOLIFY_WEBHOOK_SECRET` (chaîne aléatoire d'au moins 16 caractères), `COOLIFY_ORIGIN`, `COOLIFY_API_TOKEN` et `TYPESAFE_API_KEY`. Lancez séparément `python3 app.py --serve` et `python3 app.py --worker`, puis consultez `python3 app.py --results`. Configurez l'URL du webhook de notification : `https://VOTRE-ENTREE-AUTHENTIFIEE/webhook/VOTRE-SECRET`. Le service écoute en local ; placez une entrée HTTPS devant lui. Évitez d'inscrire cette URL dans les journaux d'accès. Coolify ne signe pas ces webhooks et sa livraison documentée ne relance pas seulement sur une réponse non-2xx : le traitement commence donc par une file SQLite persistante. Un arrêt entre la réponse de Jev et l'enregistrement SQLite peut répéter l'appel. Le masquage des secrets reste partiel ; définissez une politique adaptée avant d'envoyer des logs sensibles. L'API Jev a été testée avec des données synthétiques ; aucune instance Coolify réelle n'était disponible.

## Español

Revise los despliegues fallidos de Coolify con una decisión Jev acotada y versionada: `image`, `permissions`, `configuration`, `startup`, `network` o `review`. El webhook guarda el identificador del despliegue en SQLite y responde rápidamente; un proceso separado obtiene los registros mediante la [API de Coolify](https://coolify.io/docs/api/endpoints/deployments/get-deployment-by-uuid), selecciona la primera línea de error explícita, oculta patrones habituales de secretos y la clasifica. No ejecuta reinicios, reversiones ni despliegues. La base conserva identificadores y decisiones, nunca los registros completos. Las decisiones inciertas van a `review`.

Sin conexión: `python3 app.py --demo` y `python3 -m unittest discover -s tests -v`. Para una instalación real, defina en privado `COOLIFY_WEBHOOK_SECRET` (cadena aleatoria de al menos 16 caracteres), `COOLIFY_ORIGIN`, `COOLIFY_API_TOKEN` y `TYPESAFE_API_KEY`. Ejecute `python3 app.py --serve` y `python3 app.py --worker` como procesos separados y consulte `python3 app.py --results`. Configure la URL del webhook de notificación como `https://SU-ENTRADA-AUTENTICADA/webhook/SU-SECRETO`. El servicio escucha solo en localhost; sitúe una entrada HTTPS delante. Evite registrar la URL en los logs de acceso. Coolify no firma estos webhooks y su comportamiento documentado no reintenta solo por una respuesta distinta de 2xx; por eso se guarda primero en una cola SQLite persistente. Una interrupción entre la respuesta de Jev y la confirmación SQLite puede repetir la llamada. La ocultación de secretos es parcial; establezca una política adecuada antes de enviar registros sensibles. La API Jev se probó con datos sintéticos; no había una instancia Coolify real disponible.
